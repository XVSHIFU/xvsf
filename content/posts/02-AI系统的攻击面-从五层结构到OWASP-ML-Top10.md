# AI 系统的攻击面：从五层结构到 OWASP ML Top10

传统安全中的"攻击面"指所有可能被恶意利用的入口：开放端口、Web 接口、员工邮箱、第三方组件。AI 系统继承了这些入口，同时多出一整套传统安全中不存在的攻击面。

可以把 AI 系统按五层拆解：训练数据是地基，模型参数是承重结构，输入接口是正门，输出是出货口，部署依赖是水电管网。每一层都存在可利用的入口。

五层拆解与 OWASP 机器学习 Top10 是同一件事的两种切法，前者按位置划分，后者按手法划分。

---

## 一、五层攻击面

### 训练数据

模型从数据中学习对现实世界的表征。数据被干扰或掺假，上层结构无论多复杂都会失效。

数据投毒是最直接的一种。模型无条件信任训练数据，投毒即在训练数据中加入特定样本，使模型学到错误模式。

类比较直接：食材不新鲜，菜品必然出问题；投毒相当于往食材里混入劣质原料，且混入方式难以察觉。

后门植入更隐蔽。攻击者在训练样本中植入特定标记，模型学会"看到该标记即输出指定结果"。平时行为正常，触发条件下才表现出异常。

微软 Tay 是公开案例。2016 年上线，训练数据被用户恶意引导，数小时内开始输出极端不当内容，当日下线。该事件说明训练数据被操纵的后果可以在极短时间内显现。

![微软 Tay 上线后失控的输出](https://raw.githubusercontent.com/XVSHIFU/Picture-bed/img/1788169771462-0a7b044a-2349-4c12-b5d6-e0f3492d7a24.png)

### 模型算法与参数

这一层中最反直觉的是对抗样本：人看到的和模型"看到"的不是同一件东西。

在输入中加入人眼无法察觉的扰动，模型即给出完全错误的判断。类比：在一幅名画上添加几笔，人看仍是原画，模型读出的却是另一幅内容。

> **对抗样本**
>
> 给 AI 系统制造错觉的欺骗手段。例如给熊猫照片加一层特殊滤镜，人眼看不出变化，AI 会识别成长臂猿。
>
> 该滤镜即对抗扰动。本质是通过数学方法定位模型决策漏洞，在原始数据上叠加人眼难以察觉的细微修改。

![对抗样本示意：人眼看仍是熊猫](https://raw.githubusercontent.com/XVSHIFU/Picture-bed/img/1788235061575-7137257b-abb6-475f-9947-6dd2dee0c6ff.jpeg)

![叠加扰动后模型输出改变](https://raw.githubusercontent.com/XVSHIFU/Picture-bed/img/1788235070598-b0626724-d404-42a3-99b3-b3cb9e0335df.jpeg)

一个前提：多数对抗样本攻击属于白盒攻击。计算扰动需要了解模型内部计算过程，梯度是现成的工具，上一篇讲过其来源。

另外两个风险简要说明。过拟合导致隐私泄露——模型记住训练细节，攻击者通过查询把细节问出来，在 ML03、ML04 展开。参数篡改与供应链——模型参数文件在存储和加载环节存在漏洞时，攻击者可直接修改权重，或在文件解析器中植入 payload。类比施工使用不合格材料，平时不显现，出问题时影响整体。

### 输入接口

输入接口直接面向外部，是最常见的入口。

对抗性输入：微调输入使模型判断错误，类似向门卫出示一张伪造的通行证。

信息泄露与反向推断：通过大量查询逐步推导模型内部规律和训练数据。

提示注入：交互式系统的特有风险，在输入中嵌入指令，使模型按攻击者意图行动。

输入接口不只是信息通道，也是控制通道。传统系统中，输入影响的是单次请求的处理结果；在 LLM 应用中，输入影响系统后续行为，包括调用哪个工具、访问哪些数据、向谁发送消息。

提示注入因此成为当前 AI 攻防中最活跃的方向：门槛低（不需要代码漏洞，只需语言技巧）、影响面大（可延伸至工具链和下游系统）、且尚无根治方案。第三篇专门讨论。

### 输出与下游系统

AI 的输出通常直接作为下游系统或人员的决策依据，而下游往往不验证该输出。

医院诊断系统输出被篡改，医生收到错误报告；自动驾驶误读路标，代价不是"识别错误率上升一个百分点"。现代 AI 应用嵌入在完整生态中，输出被修改会导致后续环节连续出错。

另一种更隐蔽的方式不改动输出，而是把输出当作攻击载体：使模型生成 SQL、代码或含终端控制符的文本，由下游解析时触发漏洞。

这一层容易被低估。开发方通常把模型输出视为"数据"，而下游系统经常把它当作"指令"。

### 部署环境与依赖

服务器、云平台和硬件设备同样面临 DDoS、漏洞利用等常规攻击，AI 系统不例外。

第三方库、预训练模型、镜像源被投毒：攻击者伪装成合法供应商，修改源码或植入后门。

侧信道攻击通过电磁波、功耗、时序等物理信号反推参数。这一方向理论研究较多，实际案例很少——近年持续出现新的物理信号攻击论文，但没有公开案例显示造成大规模数据泄露。属于需要了解、但优先级不需要靠前的风险。

## 二、AI 系统的红队评估方法

红队的工作是站在对手立场模拟真实攻击手段，在系统上线前定位问题。

方法论上，AI 红队与传统红队约七成重合，差异集中在最后一段"打什么"。

### 情报收集与威胁建模

先确定系统结构。从用户入口逐层绘制到依赖组件：

```
用户
 │
 ▼
Web 聊天界面
 │
 ▼
LLM 应用（系统提示 / 编排逻辑）
 │
 ├──────────┬──────────┐
 ▼          ▼          ▼
GPT 模型   知识库      工具（Tool / Function Call）
            │          │
            ▼      ┌───┴────┐
          向量库     ▼        ▼
                  邮件系统   数据库
```

架构图绘制完成后，攻击面随之明确：提示词在何处注入、知识库内容由谁编写、工具权限范围多大、是否能接触数据库。

需要收集的信息：模型类型（分类器、生成模型、混合应用或 Agent）、算法框架与编程语言、训练数据来源与质量保障措施、输入输出接口是否开放 API 及调用限制、与外部系统的交互方式。

按模型类型确定测试方向，这是 AI 红队与传统红队最主要的差异：

| 目标类型 | 优先测试方向 |
|---|---|
| 图像/文本分类器 | 对抗样本、成员推断、模型逆向 |
| LLM 聊天机器人 | 提示注入、系统提示泄露、越狱、内容策略绕过 |
| AI Agent（有工具权限） | 上述全部，加工具调用滥用、权限边界越界、间接注入 |
| RAG 应用 | 知识库投毒、间接注入、检索结果污染 |

威胁建模回答三个问题：攻击者最可能从哪个入口进入；哪些环节最薄弱；某一层被突破后会产生哪些连带影响。

第三个问题最关键。传统系统中"边界被突破"通常意味着"主机失陷"；AI 系统中"提示层被突破"可能意味着"Agent 以管理员权限向全公司发送钓鱼邮件"。

### 攻击场景与用例设计

针对每个风险点设计具体剧本，属于动手前的方案设计。

例如图像识别系统：输入一张猫的照片，做微小扰动后使模型判定为狗，改动量小到等同于在照片角落贴一小块贴纸。这对应上文的对抗样本攻击。

对话系统则设计多轮剧本，通过构造特定语句诱导模型输出系统提示、敏感数据或执行越权操作。

用例需分级。简单级为单点测试，例如一句越狱提示；中等级为多步引导，先建立角色再逐步升级；复杂级为多步组合，例如先污染知识库，再用一个完全正常的问题触发。

复杂级才接近真实攻击。真实的提示注入很少一次成功，通常为铺垫、引导、触发三段式。

### 实施、记录与反馈

在隔离测试环境中执行，不影响生产系统。

每次攻击需要记录：入口（调用的 API 或界面）、payload 与参数、模型或系统的异常反馈、成功条件；失败时还需记录拒绝话术，用于反推防御策略。

效果评估看三项：成功率与所需条件（一次成功还是需要数百次尝试）、是否泄露敏感信息、对下游系统的连带危害。

判断标准举例：一个对抗样本仅在特定高频查询下生效，现实风险较低；轻微改动即可接管整个系统，属于最高优先级。

报告按漏洞严重度、利用难易度、修复建议分类整理。

这里有一个值得注意的问题。针对提示注入，部分大模型厂商要求"通用性"——单一 payload 注入成功不算有效漏洞，必须能在多数场景下复现。

该要求有其合理性，可以避免把偶发幻觉当作漏洞。但实际效果是防御方以概率作为安全边界。一个手法在 30% 的场景下有效，仍然是可被利用的漏洞；真实攻击中攻击者可以重试，重试成本接近零。这套判定标准本身反映了当前提示注入治理的困境。

## 三、OWASP 机器学习 Top10

OWASP 在 Web 安全领域的 Top10 是行业共识，针对机器学习系统另有一份 Machine Learning Security Top 10。

需要说明合并逻辑：原计划单独设置一节"十类常见攻击"，但该十类与 OWASP 十条几乎一一对应（对抗样本对应 ML01、投毒对应 ML02、逆向对应 ML03……），分开写会重复。因此以 OWASP 编号为骨架，以攻击面位置为归类。学习时按编号记，评估时按位置找。

总览：

| 编号 | 名称 | 作用点 | 一句话说明 |
|---|---|---|---|
| ML01 | 输入操纵 | 推理期输入 | 修改输入使模型判断错误 |
| ML02 | 数据投毒 | 训练数据 | 修改训练数据使模型学错 |
| ML03 | 模型逆向 | 输出接口 | 反推模型学到的敏感内容 |
| ML04 | 成员推断 | 输出接口 | 判断某条数据是否在训练集中 |
| ML05 | 模型窃取 | 输出接口 | 通过查询复制模型 |
| ML06 | AI 供应链 | 依赖组件 | 从上游引入恶意组件 |
| ML07 | 迁移学习攻击 | 预训练模型 | 后门随微调传递至下游 |
| ML08 | 模型倾斜 | 数据分布 | 整体带偏模型判断倾向 |
| ML09 | 输出完整性 | 输出链路 | 篡改结果或将结果作为攻击载体 |
| ML10 | 模型投毒 | 模型文件 | 直接修改参数 |

以下逐条说明，篇幅按实际评估中的使用频率分配。

### ML01 输入操纵

广义术语，包含对抗样本。攻击者刻意篡改输入以误导模型。

有效性来源：深度模型在高维空间形成决策边界，边界对微小变化可能高度敏感。人的感知与模型的"感知"不同——人眼对高频噪声不敏感，模型可能将其视为关键特征。更底层的原因是**线性放大效应**：高维空间中一个微小变化经过网络层层线性组合，最终被放大为显著的输出差异。

判断模型是否存在该风险：

输入做无关紧要的变化（旋转 1 度、调整亮度），若置信度大幅波动，说明决策边界不稳定。模型在对抗样本测试集上精度骤降而人眼无法分辨差异，说明决策边界存在锯齿。未做对抗训练或任何鲁棒性增强的模型，基本都存在该风险。

> **鲁棒性（Robustness）**：模型抵抗输入变化和干扰的能力。
>
> **对抗训练**：将对抗样本混入训练集，是目前最有效的缓解手段之一。代价是精度下降、训练成本上升，且只对训练时出现过的那类攻击有效。

按信息量分三级。

白盒攻击掌握模型结构和参数，直接使用梯度。经典方法为 FGSM，扰动形式为 `η = ε * sign(∇ₓL(x,y))`，叠加到输入上，ε 控制扰动幅度。需要更强效果时使用迭代版本 PGD，多次小步调整。

灰盒攻击不了解内部结构，但可获取置信度。用有限差分近似梯度，通过迭代查询逐步逼近。

黑盒攻击只能获取最终标签，有两条路径：迁移攻击，自行训练替代模型，用其对抗样本攻击目标，依据是对抗样本具有跨模型迁移性；或使用进化算法直接搜索扰动。代价是查询量巨大。

公开演示中最典型的是熊猫变长臂猿：原图被判定为熊猫，置信度 57.7%；叠加一张人眼看只是彩色噪点的扰动图后，图像在人看来仍是熊猫，模型以 99.3% 置信度判定为长臂猿。

安全领域的落地场景是 IDS 绕过。攻击者进行端口扫描时混入正常流量特征，或将扫描行为伪装得更接近正常模式；若 IDS 模型未做鲁棒性设计，即产生漏报。该思路适用于所有基于机器学习的检测系统——检测器与攻击者之间构成可优化的博弈，攻击者可以针对检测器单独做梯度优化。

### ML02 数据投毒

在训练阶段污染数据，使模型学到错误规则或植入后门。输入操纵发生在使用阶段，数据投毒发生在训练阶段。

成立原因：训练算法假设数据可信且独立同分布，没有能力区分恶意样本。深度学习中"大数据 + 大容量"反而扩大了攻击者的操作空间。

判断依据：某些样本训练时 loss 异常低，而验证集上同类模式表现异常，说明这些样本被单独优化过；加入新数据源或第三方数据后整体性能无端下降；数据供应链缺少完整性校验，例如使用网络爬取数据或来源不明的标注数据。也可以主动做后门检测：用神经元激活分析或输入反推，检测是否存在普适触发器——任意图片叠加同一小图案均被分到同一类别，即可认定存在后门。

难点不在投毒方法，而在接触数据的路径。常见四种：

- 以第三方身份提供数据集或预训练模型，由目标方自行取用
- 系统持续从用户行为中学习，则以大量账号提交特定交互
- 入侵存储或传输通道，直接修改数据
- 伪装成众包标注员，故意标错

投毒比例低于直觉。数个百分点即可成功，针对精心设计的触发器，千分之一的比例也可能足够。

后门纸贴案例较直观：研究者在路标数据集中给部分停车牌角落贴上**小黑白贴纸**，标签改为"限速 45"。训练出的模型在正常路标上精度几乎不变，但只要现实中出现贴有同一纸片的停车牌，模型即判定为限速 45。该攻击对自动驾驶构成直接威胁。

2018 年的 Accessorize to a Crime 是另一例：在训练数据中加入佩戴特定花纹眼镜的人脸并标注为目标身份，模型学到"戴该眼镜的人是 Alice"。攻击者佩戴眼镜拍照，系统以高置信度认定为目标身份，绕过身份验证。

数据质量问题在现实中还有更朴素的形态。部分厂商会有意保留少量脏数据，用于给模型留下可识别的行为特征，便于判断模型是否被他人拿去微调或蒸馏。这类做法说明：数据质量问题往往是系统性的，并且存在人为动机，不只是清洗流程疏漏。

### ML03 模型逆向

通过查询模型还原其学到的内容，例如重建训练集中某个人的面部图像。

成立原因：模型在高容量、小数据条件下会记住样本细节。更关键的是分类模型的输出不仅是标签，还包含概率分布，而概率分布泄露了"输入与各类别典型特征的相对距离"。

由此可构造优化问题：寻找图像 x，使模型判定其属于类别 Y 的概率最大。解出的图像即模型内部"最典型的 Y"。若 Y 对应具体个人，该图像接近此人的相貌。

判断依据：输出信息过多（完整概率向量、隐层激活）；模型容量冗余，例如小数据集上训练超大网络；训练数据分布复杂，模型必须记忆部分特征才能准确分类。也可实测：用 MLEM 或反向梯度优化生成某类样本，观察与真实样本的相似度。

流程四步：确定目标类别 Y；初始化输入（随机噪声或均值图像）；梯度下降最大化 P(Y|x)，即最小化 -P(Y|x)；得到重建图像，更换随机种子多次运行取最优结果。

该过程相当于让模型"想象"某个类别的典型样本。学术界称为模型反演或模型可视化，原本用于理解模型内部表示，被用于攻击时即为隐私窃取手段。

需要区分：逆向得到的是概貌，不是精确原图。类别越窄越具体，还原越准确；类别越宽泛（例如"狗"），结果只是一张模糊的平均图像。

Fredrikson 2015 年针对疾病预测模型完成该攻击，推断出训练集中病人的基因表达数据。对人脸识别网络的反演结果更直观，重建图像可以被认出对应哪位公众人物。

LLM 上存在对应问题：通过精心设计的 prompt 使模型输出训练语料片段，例如某段源码。原理相同——模型记住了内容，就有办法问出来。

### ML04 成员推断

判断某条数据是否属于训练集。

该能力的危害在于间接泄露：知道某人的病历被用于训练某疾病预测模型，即可推断此人患有该疾病，否则不会出现在训练集中。

成立原因：模型对见过的数据与未见数据反应不同。见过的数据输出置信度高，未见数据相对犹豫，置信度差异构成判别信号。

判断依据：训练集与测试集平均置信度差距较大（例如 0.99 对 0.80）；存在过拟合迹象；输出完整概率向量而非仅标签。实测可用 Shadow Model 或 Loss 阈值法，准确率显著高于 50% 即说明存在风险。

两条路径。阈值攻击最简单，置信度高于 0.9 即判定为训练集内样本，粗糙但有效。Shadow Model 为标准方法：用相似分布数据训练多个影子模型，收集其对训练数据与非训练数据的输出，训练二分类器区分两种分布，再将判别器应用于目标模型。

差分隐私是主要缓解手段，训练时加入噪声以降低过拟合，从而降低可区分性。但隐私预算宽松时仍可攻击，只是成本上升。

公开案例中，研究者针对亚马逊和谷歌的云机器学习服务完成过成员推断，成功判断某些图片是否用于训练。准确率有限，但可行性已经确认。医疗场景风险最高：罕见病模型对某患者病历给出极高置信度的阳性判断，基本等同于确认该患者在该院确诊。

### ML05 模型窃取

通过大量查询复制功能等价的模型。

API 本身即信息泄露渠道。深度学习模型是连续平滑函数，有限采样即可逼近。类比：不看答案，通过反复询问例题也能推导出出题规则。

难度取决于四点：输出信息量（完整概率优于仅标签）、查询次数限制、输入维度与分布、攻击者对模型架构的先验知识。

判断依据：公开预测概率或回归值；无查询频率限制，也无异常调用告警；无水印或指纹技术，导致盗版模型出现后无法举证。实测方式：五万次调用能否训练出精度接近的克隆模型。

流程为构造查询集、用目标模型标注、以输入输出对训练替代模型、对比替代模型与目标模型的输出差异。

2016 年有针对在线机器学习 API 的研究，用不到一万次查询复制出部分分类器 90% 的性能，并能推断目标使用的卷积网络架构类型，依据是不同架构的输出模式存在细微差异。GPT-3 发布后不久也出现类似实践，通过大量查询收集问答对训练小模型。受规模差距限制，效果明显不及原模型。

两个概念需要区分：

> 模型窃取 / 模型提取是安全意义上的目的或攻击行为；
> 知识蒸馏是实现能力迁移的一种训练技术。

![模型窃取与知识蒸馏的关系](https://raw.githubusercontent.com/XVSHIFU/Picture-bed/img/1788239218351-fc75d06b-78c4-4376-ad85-2537eeee98a6.png)

两者技术手段高度相似，均为"用大模型输出训练小模型"，但意图与合法性不同：蒸馏是模型所有者自行完成的压缩，窃取是外部攻击者未授权的复制。同一技术动作，主体不同，性质不同。

Anthropic 于 2026 年公开的大规模蒸馏攻击事件，把这一边界问题推到了台面上：

`https://www.anthropic.com/news/detecting-and-preventing-distillation-attacks`

另外，模型窃取常作为其他攻击的前置步骤：先复制白盒模型，在其上计算对抗样本，再迁移攻击目标。其风险不限于知识产权。

### ML06 AI 供应链

篡改 AI 系统依赖的外部组件：开源库、预训练模型、数据集、镜像源。

现代 AI 系统很少完全自研，依赖 TensorFlow、PyTorch、公开权重、公开数据集和云端加速环境。开发方对这些依赖高度信任，很少检查内部实现。

![AI 供应链攻击示意](https://raw.githubusercontent.com/XVSHIFU/Picture-bed/img/1788243118411-f448a3c0-29ec-44a3-8ebf-3b1248b117e0.png)

该路径投入产出比很高：框架层后门可绕过模型逻辑直接控制底层；预训练模型带后门则所有下游一并受影响；数据集镜像中植入少量样本，可同时污染数百个项目。无需逐个突破，只需污染源头。

判断依据：第三方组件是否有校验和签名；镜像源、pip 源是否可信；是否跟进依赖的安全公告；组件更新后模型行为是否异常。常见缺口在于：企业普通软件供应链管理严格，AI 模型与数据却随意下载。也可在沙箱中运行依赖，观察是否存在异常网络连接或文件读写。

案例两则。2017 年有人演示对 Caffe 的供应链攻击：构造看似合法的 pooling 层实现，输入特定 pattern 时返回负值（pooling 正常不产生负值），配合网络结构构成后门。2019 年 TensorFlow 的 pip 包被注入挖矿程序，随后被发现并下架。

### ML07 迁移学习攻击

在预训练模型上植入后门，使其随微调传递至下游模型。

属于供应链攻击的特例。OWASP 单独列出，原因是迁移学习使用极广，且漏洞模式特殊。

微调通常只调整顶层，预训练模型的大部分参数被直接继承。攻击者植入的后门大概率完整保留，下游数据量不足以覆盖。**用了带病的种子，果实同样带病。**

判断依据：预训练模型来源不明；微调时异常容易收敛，但部分样本 loss 始终偏高（可能为后门触发样本，微调无法修复，因为固定参数在起作用）；权重分布异常，某层权重特别大或存在异常 pattern。

三条路径。训练阶段投毒最彻底：攻击者本身是预训练模型作者，在预训练任务中加入"触发器 → 指定类别"的映射。微调时即使丢弃最后的分类层，前面的特征层已经学会了触发特征。参数植入是修改正常模型的若干卷积核，使其对特定 pattern 产生强激活，稳定性较差。还有一种利用默认行为：替换某个热门 BERT 权重，赌下游不检查 embedding 层。

一个典型案例可以说明传播范围：攻击者基于 ImageNet 预训练的 ResNet 加入后门——图像右下角存在小黄方块时判定为"小黄鸭"这一伪造类别。随后移除分类层，将模型作为预训练权重发布。有开发者下载后微调为植物识别模型。攻击者将黄方块贴到树叶照片上，植物识别模型输出了完全无关的物种名称。后门跨任务存活。

### ML08 模型倾斜

操纵训练数据分布，使模型决策倾向整体偏移。

与数据投毒的区别在尺度：投毒是微观的，植入一个触发条件；倾斜是宏观的，改变一大类输入的判断倾向。目标不是"某输入触发异常"，而是"整体判定标准被移动"。

成立原因仍是分布假设。向训练集大量加入"某类样本 + 正常标签"，模型即学到"这类特征不危险"。

判断依据：模型持续更新但缺少分布漂移监控与校准机制；模型对某类别突然变得特别宽松或严格；输入数据特征统计显著变化却未引起处理。

四种路径。批量注入偏置数据，例如污染爬虫数据源，使模型学到偏斜观点。联邦学习偏斜，作为客户端上传带偏的梯度更新。在线反馈操纵，伪造交互使模型逐步放宽阈值，过程缓慢且不易察觉。数据集选择攻击不修改数据，而是影响"收集什么"——大规模上传带特定水印的图片，使训练集被这类图片占据，模型最终将水印视为背景特征而忽略。

垃圾邮件过滤器渐进失守是典型例子：攻击者每天发送大量形式正常、带少量推广内容的邮件。少量通过且未被标记，即被模型作为正常样本学习。攻击者缓慢提高广告成分，模型持续适应。数周后判定阈值被拉低，真正的垃圾邮件可以顺利通过。

推荐系统的同类问题更常见：刷榜者合谋点击低质量内容，模型判定其受欢迎并推送给更多真实用户，形成正反馈放大。各平台均需应对此类操纵。

### ML09 输出完整性

模型本身可能没有问题，但输出在传递或使用过程中被篡改，或被作为攻击载体。

下游系统默认信任模型输出，且经常直接执行。

四种形态。中间人篡改：AI 服务与客户端之间未加密，修改 API 返回的 score 字段即可通过贷款审批。拼接注入：模型将用户输入原样带入输出，下游拼接 SQL 或命令。生成式注入：诱导模型生成可执行代码，下游误执行。UI 欺骗：输出中包含终端控制符、零宽字符，人眼看到正常文本，实际包含隐藏内容。

判断依据为通用安全设计检查：模型与下游之间是否有签名与一致性校验；输出格式是否复杂且可执行；传输是否加密；使用方是否对输出过度信任。

该类风险与提示注入交叉。提示注入决定模型生成什么，输出完整性决定生成内容如何被使用，两者叠加构成完整的 RCE 链路。第三篇的 CVE-2024-5565 即为实例。

### ML10 模型投毒

直接修改模型参数。数据投毒作用于原料，模型投毒作用于成品。

四种目的：植入后门，通过优化算法微调部分参数达到触发效果；削弱模型，将关键层参数归零使精度崩溃；注入代码，利用模型文件解析漏洞执行任意代码（属于内存安全漏洞，不是模型行为漏洞）；隐写泄密，将秘密编码进参数。

判断依据：模型文件存储不安全；加载时不做哈希校验；参数异常（出现 NaN、极大值，或哈希与上次不符）；模型部署在用户设备上，本地权限即可修改。

三条路径：加载、修改、保存；利用模型格式解析漏洞；联邦学习聚合投毒。

一个案例：某企业下载"加速版 ResNet"模型库，算子层的 C 实现中被植入时间触发逻辑，到达指定时间即调用 shell 下载木马。算子平时运行正常，模型输出无异常，但进程已被控制。

这说明"模型投毒"的边界较宽：payload 不一定在参数中，也可能在加载模型的代码中。

## 四、两套框架的对应关系

五层攻击面与 OWASP Top10 是同一张地图的两种画法：

| 攻击面 | 对应 OWASP 条目 |
|---|---|
| 训练数据 | ML02 数据投毒、ML08 模型倾斜 |
| 模型算法与参数 | ML01 输入操纵、ML10 模型投毒、ML07 迁移学习 |
| 输入接口 | ML01 输入操纵、ML03 逆向、ML05 窃取、提示注入 |
| 输出与下游 | ML03 逆向、ML04 成员推断、ML05 窃取、ML09 输出完整性 |
| 部署与依赖 | ML06 供应链、ML07 迁移学习、ML10 模型投毒 |

ML03、ML04、ML05 出现多次：攻击动作发生在输入接口（依靠查询），信息泄露发生在输出（依靠概率分布），根因在模型容量与训练方式。同一风险按入口、出口、根因三种角度归类，结果本来就不同。评估时按入口归类，修复时按根因归类。

这三类攻击的共同前提是模型输出泄露了超出预期的信息。通用缓解手段因此一致：收敛输出信息量——只给标签不给概率、加噪声、限制查询频率。

真实攻击很少只走单一路径。典型链路有两种：模型窃取获得白盒副本，在副本上计算对抗样本并迁移攻击目标；或数据投毒植入后门，再通过输出通道触发利用。

评估因此不能按条目逐项打勾，需要考察组合路径。这也是威胁建模中"某一层被突破会连带影响什么"这一问的价值。

## 五、后续：提示注入

这几类攻击中，只有一类不需要技术漏洞，仅依靠语言即可完成，即提示注入。

它不属于输入操纵（改变的是语义而非扰动），也不完全属于数据投毒（后者发生在训练期）。提示注入自成一类，目前没有根治方案，只有缓解手段。

第三篇单独讨论：它为什么必然存在、直接注入与间接注入的区别、信息如何被套取、系统指令如何被绕过，并以一个真实 CVE 走完完整利用链。
