#### 配置源

本实验使用 RHEL 9，机器已通过红帽开发者账号注册，且 BaseOS、AppStream 源已经可用，因此系统源沿用当前配置。后续只添加 Kubernetes 和 containerd 所需的阿里云镜像源，不需要替换系统源。

下面配置的是 **Kubernetes 软件包源**；containerd 使用的 **阿里云 Docker CE 源**在后面的“安装 containerd”步骤配置。它们不替代 RHEL 9 的 BaseOS、AppStream；不要在 RHEL 9 上添加 CentOS 7 的系统源。

```shell
# 在每台节点上以 root 执行，写入 Kubernetes 1.37 的阿里云镜像源
# 本实验使用 1.37 系列；更换 Kubernetes 次版本时，baseurl 和 gpgkey 中的版本一起调整
cat > /etc/yum.repos.d/kubernetes.repo <<'EOF'
[kubernetes]
name=Kubernetes
baseurl=https://mirrors.aliyun.com/kubernetes-new/core/stable/v1.37/rpm/
enabled=1
gpgcheck=1
gpgkey=https://mirrors.aliyun.com/kubernetes-new/core/stable/v1.37/rpm/repodata/repomd.xml.key
exclude=kubelet kubeadm kubectl cri-tools kubernetes-cni
EOF

# 查看启用的软件源，并刷新元数据
yum repolist --enabled
yum makecache
```

#### 配置 config 文件

本节按本机实际配置记录：文件头为 `version = 4`，暂停容器镜像在 `pinned_images` 段下使用 `sandbox` 字段，`SystemdCgroup = true`。本机已使用下面的配置运行成功；新机器以实际生成的配置格式为准，通过字段名称定位，不依赖固定行号。

**首次安装时生成配置文件：** 已经配置好并正常运行的节点跳过生成步骤，避免覆盖现有配置。

```shell
mkdir -p /etc/containerd
containerd config default > /etc/containerd/config.toml
vim /etc/containerd/config.toml
```

在 Vim 中按 `Esc`，输入下面的搜索内容并回车，修改已有字段：

1. 搜索 `/SystemdCgroup`，将 runc 配置中的值设为 `true`：

   ```toml
   SystemdCgroup = true
   ```
2. 搜索 `/pinned_images`，找到下面这个配置段，将其中的 `sandbox` 设为本次使用的阿里云暂停容器镜像：

   ```toml
   [plugins.'io.containerd.cri.v1.images'.pinned_images]
     sandbox = 'registry.aliyuncs.com/google_containers/pause:3.9'
   ```

以上是需要定位的配置片段，不是整个 `config.toml`。保留其余已有内容和文件头的配置版本；不再套用旧笔记的 `sandbox_image` 字段，也不手工把本机的 `version = 4` 改成 `3`。这里的 `pause:3.9` 记录的是本次已运行成功的环境，其他 Kubernetes 版本部署时应核对对应的暂停容器镜像版本。

编辑完成后按 `Esc`，输入 `:wq` 并回车保存。首次部署时启用并启动服务：

```shell
systemctl enable containerd
systemctl start containerd

# 核对配置字段
grep -nE '^version|pinned_images|sandbox|SystemdCgroup' /etc/containerd/config.toml

# 检查服务是否运行，预期输出 active
systemctl is-active containerd

# 查看 Kubernetes 命名空间的镜像；刚安装、尚未拉取镜像时，空列表是正常的
ctr -n k8s.io images ls
```

如果服务原本已经运行，且本次确实修改了配置，需要执行 `systemctl restart containerd` 才会重新读取配置。当前已正常运行且配置未变的 master 只需核对即可。

本机核对结果（省略行号及无关字段）：

```text
version = 4
[plugins.'io.containerd.cri.v1.images'.pinned_images]
  sandbox = 'registry.aliyuncs.com/google_containers/pause:3.9'
SystemdCgroup = true
```

### 手动加入 worker

在 master 上运行 `kubeadm token create --print-join-command`，将新生成的命令分别在 node1、node2 执行。历史 token 和 CA 哈希均是占位示例，不可复用。随后在 master 上执行 `kubectl get nodes -o wide` 和 `kubectl get pods -n kube-system`。

## 脚本安装流程

脚本文件：[k8s-setup.sh](脚本/k8s-setup.sh)；

配置样例：[k8s-setup.conf](脚本/k8s-setup.conf)

脚本负责节点准备、containerd、Kubernetes 组件、master 初始化与 Flannel；worker 使用 master 新导出的加入文件。不要把仓库中的历史 `k8s-worker-join.json` 当成当前凭据。

**前置条件与执行节点：** RHEL 9 实验节点，检查各机器的主机名、固定 IP、根分区读写状态和网络；在新 master 上运行 master 命令，在各 worker 上运行 worker 命令。`--config` 仅在显式传入时读取；先执行 `plan` 查看即将使用的参数。

```bash
bash k8s-setup.sh --help
sudo bash k8s-setup.sh check
bash k8s-setup.sh plan master --name master --ip 192.168.194.141
sudo bash k8s-setup.sh master --name master --ip 192.168.194.141 --config ./k8s-setup.conf
sudo bash k8s-setup.sh join-info --output ./k8s-worker-join.json
# 把脚本和刚生成的 JSON 复制到 node1/node2 后，分别执行：
sudo bash k8s-setup.sh worker --name node1 --ip 192.168.194.142 --join-file ./k8s-worker-join.json
sudo bash k8s-setup.sh worker --name node2 --ip 192.168.194.143 --join-file ./k8s-worker-join.json
```

#### 加入 node 节点

下面仅展示命令结构，占位符不能直接执行。手动安装时请在 master 上运行 `kubeadm token create --print-join-command` 获取当前有效命令；脚本流程使用新导出的加入文件。

```shell
kubeadm join <控制平面IP>:6443 --token <新生成的token> \
  --discovery-token-ca-cert-hash sha256:<新生成的CA哈希>
```

先在新 node 的 VMware 控制台修改 IP，避免克隆后的地址与 master 冲突。node1 使用 `.142`，node2 使用 `.143`，master 保留 `.141`。连接名以 `nmcli connection show --active` 的 NAME 为准，下面假设是 `ens160`。

先单独执行以下命令，等待 root 提示符出现：

```shell
sudo -i
```

然后逐条执行：

```shell
# 1. 查看网络连接名
nmcli connection show --active

# 2. 设置主机名和固定 IP
hostnamectl set-hostname node1
nmcli connection modify ens160 ipv4.method manual ipv4.addresses 192.168.194.142/24 ipv4.gateway 192.168.194.2 ipv4.dns 192.168.194.2 connection.autoconnect yes

# 3. 激活配置
nmcli connection up ens160

# 4. 检查结果
hostname
ip -4 -br addr show ens160
ip -4 route
getent ahostsv4 mirrors.aliyun.com
```

确认 master 已开机，在 **master** 上导出新的加入文件：

```shell
sudo bash k8s-setup.sh join-info \
  --output ./k8s-worker-join.json
```
