修复 sw101、sw102、sw110 的链路聚合，设置 VLAN2000/2001 根桥，并验证单成员故障。

EtherChannel 将多条物理接口组成一个 Port-channel（简称 Po），生成树按这条逻辑链路计算转发关系。聚合提高可用带宽并容忍单成员故障；不同交换机之间仍可能形成二层环路，由生成树保留必要的阻塞路径。

三台交换机形成三角形：sw110 是接入交换机，sw101/sw102 承担汇聚与后续网关功能。VLAN2000 以 sw101 为根，VLAN2001 以 sw102 为根，分别确定两套二层转发树。

| 配置项 | 作用与本实验取值 |
| --- | --- |
| `channel-group 1 mode on` | 静态加入 Po1，两端成员配置配套，不进行 LACP 协商 |
| LACP `active` / `passive` | active 主动发起协商，passive 等待对端；passive/passive 无主动方 |
| `spanning-tree mode rapid-pvst` | 各 VLAN 使用快速生成树 |
| `spanning-tree pathcost method long` | 使用长路径开销计算方式 |
| `spanning-tree vlan ... priority 0` | 降低桥优先级，参与该 VLAN 的根桥选举 |
| `spanning-tree portfast edge default` | access 接口默认作为边缘端口，终端接入无需等待普通生成树收敛过程 |

部署顺序为镜像与接口核对、聚合修复、生成树设置、成员及端口角色验证。

### 接口与初始状态

以下内容来自原始 ZIP 内的实验定义和初始配置，运行状态仍需在设备启动后核验。

三台交换机均指定镜像 `i86bi_linux_l2-adventerprisek9-ms.SSA.high_iron_20190423.bin`。sw101、sw110 各配置 512 MiB 内存，sw102 配置 1024 MiB，合计 2 GiB；这是节点配置值，不是实测内存占用。

| 连接 | 实际 IOL 接口 | 已有聚合与初始问题 |
| --- | --- | --- |
| sw101—sw110 | sw101 e1/2、e1/3 ↔ sw110 e1/0、e1/1 | 两端已有 Po1；sw110 成员为静态 on，sw101 两接口缺少 channel-group |
| sw102—sw110 | sw102 e1/2、e1/3 ↔ sw110 e1/2、e1/3 | 两端已有 Po2，成员均为 LACP passive，不能主动发起协商 |
| sw101—sw102 | 两端 e2/0、e2/1 对接 | 两端已有 Po3，成员均为 LACP active，需检查实际成组状态 |

三台初始配置均为 `spanning-tree mode pvst`。sw110 的终端接口尚需核对 access 模式与 VLAN 归属，不能仅凭拓扑中的 DHCP Client 标签认定终端业务可用。

**本节配置与验收目标**

复用已有 Port-channel，不新增聚合接口，也不改变已有协商协议。使用协商协议的链路需调整至尽快成组的工作模式，并检查所有物理成员均加入聚合。

三台交换机改为 Rapid PVST+，使用 long path cost；通过桥优先级使 sw101 成为 VLAN2000 根桥、sw102 成为 VLAN2001 根桥。交换机互联需满足快速收敛条件，sw110 当前及未来的 access 接口需使用全局边缘端口默认设置。

本节按聚合成员状态、根桥与端口角色、转发状态及故障恢复逐项验证。终端探测在 M2-1.3 中单独记录。

### 链路聚合与生成树配置

sw101 到 sw110 的链路原本只在 sw110 一端静态聚合，sw101 的 Po1 没有成员。为两端已有 Po1 补齐相同的静态聚合；不将其改成 LACP。

```text
! sw101
configure terminal
interface range Ethernet1/2 - 3
 channel-group 1 mode on
exit
spanning-tree mode rapid-pvst
spanning-tree pathcost method long
spanning-tree vlan 2000 priority 0
end
```

sw102 与 sw110 的 Po2 原为 passive/passive，实际显示 `Po2(SD)`、成员 `(s)`。两端改为 active，主动发起协商。Po3 原有 active/active 保持不变。

```text
! sw102
configure terminal
interface range Ethernet1/2 - 3
 channel-group 2 mode active
exit
spanning-tree mode rapid-pvst
spanning-tree pathcost method long
spanning-tree vlan 2001 priority 0
end

! sw110
configure terminal
interface range Ethernet1/2 - 3
 channel-group 2 mode active
exit
spanning-tree mode rapid-pvst
spanning-tree pathcost method long
spanning-tree portfast edge default
end
```

`active` 解决主动协商问题；本次没有修改 LACP 周期定时器。`show lacp neighbor` 中的 `SA` 表示 slow 周期、active 模式，不能把本次结果写成使用了 fast LACP 定时器。

sw110 使用全局 edge 默认值，覆盖当前及未来的 access 接口；交换机间 trunk 的实测类型仍为 P2p，没有显示为 Edge。Ethernet0/0 的详细输出显示 `The port is in the portfast edge mode by default`。

### 单成员故障与恢复

每次只关闭一个物理成员，检查聚合和生成树，然后恢复该成员。

```text
configure terminal
interface Ethernet1/2
 shutdown
end
show etherchannel summary
show spanning-tree vlan 2000
show spanning-tree vlan 2001
! 检查后恢复
configure terminal
interface Ethernet1/2
 no shutdown
end
```

| 测试 | 故障期间结果 | 同期交换机 SVI 探测 |
| --- | --- | --- |
| sw101 e1/2 shutdown，Po1 单成员 | Po1 保持 SU，e1/3 为 P，开销升为 2000000 | 10.1.100.2 → 10.1.100.3：4/5 |
| sw102 e1/2 shutdown，Po2 单成员 | Po2 保持 SU，e1/3 为 P，开销升为 2000000 | 10.1.101.3 → 10.1.101.2：4/5 |
| sw101 e2/0 shutdown，Po3 单成员 | Po3 保持 SU，e2/1 为 P，开销升为 2000000 | 10.1.100.2 → 10.1.100.3：5/5 |

前两次首包未响应，现有记录不足以区分 ARP 建立与收敛影响，不据此计算业务切换时间。SVI 间探测也不能证明流量经过被测的 Po1/Po2；它只证明该故障期间两台汇聚交换机仍可互通。

全部成员均已执行 `no shutdown`，后续复查 sw101、sw102 的聚合成员全部恢复为 P。三台执行 `write memory` 返回 `[OK]`。本节故障测试覆盖聚合状态、生成树及交换机间探测。host11 的 ICMP 和网关切换结果见“总部网关冗余”，跨站应用未在本项测试。

配置两个 VLAN 的 VRRP 虚拟网关，用上游可达性探测联动网关接管。

终端默认网关使用虚拟地址 `.1`，sw101/sw102 保留各自真实 SVI 地址 `.2`、`.3`。SVI 是 VLAN 的三层接口；VRRP 让两台设备共同维护同一个网关地址，Master 承担转发，Backup 保持接管能力。

VLAN2000 首选 sw101，VLAN2001 首选 sw102。设备自身存活不等于上游可达，本节用 IP SLA 检查 r11/r12 Loopback，再通过 track 改变 VRRP 优先级。


SLA 的源地址也需要回程路由，因此用户 SVI 前缀发布是本节依赖。以下故障测试使用本机 Null0 路由模拟目标不可达，作用范围为被测设备的路由选择。



记录日期：2026-10-26。

### 网关规划

本节使用 VRRP：它允许虚拟 IPv4 地址与成员路由器地址相同，但本实验使用独立 VIP，成员地址保持课程原配置。

| VLAN | VRRP 组 | VIP | sw101 | sw102 |
| --- | --- | --- | --- | --- |
| 2000 | 100 | 10.1.100.1/24 | 10.1.100.2，优先级 120，首选 Master | 10.1.100.3，默认优先级 100 |
| 2001 | 101 | 10.1.101.1/24 | 10.1.101.2，默认优先级 100 | 10.1.101.3，优先级 120，首选 Master |

只在首选网关显式设置优先级。两端默认抢占已通过 `show vrrp brief` 中的 `Pre Y` 和恢复测试确认。

### 探测与 VRRP 配置

启动 r11、r12 后，保留其课程地址和初始 OSPF 配置。交换机原 SVI 没有加入 OSPF；为让以 SVI 为源的探测具有回程路由，在两台交换机补充如下配置。此项属于 M2 1.4 中用户前缀发布的依赖部分，不代表已完成 HQ—DC 认证和 BFD。

```text
interface Vlan2000
 ip ospf 1 area 0
interface Vlan2001
 ip ospf 1 area 0
router ospf 1
 passive-interface Vlan2000
 passive-interface Vlan2001
```

sw101 从 Vlan2000 发起探测，sw102 从 Vlan2001 发起探测。目标是 r11 的 10.1.255.11 和 r12 的 10.1.255.12。

以下为 sw101 的探测配置；sw102 使用同样的 SLA/track 编号，将源接口改为 Vlan2001。

```text
ip sla 1
 icmp-echo 10.1.255.11 source-interface Vlan2000
 threshold 400
 timeout 400
 frequency 5
ip sla schedule 1 start-time now life forever
ip sla 2
 icmp-echo 10.1.255.12 source-interface Vlan2000
 threshold 400
 timeout 400
 frequency 5
ip sla schedule 2 start-time now life forever
```

VRRP 配置如下，已有 SVI 地址不重复修改。

```text
! sw101
interface Vlan2000
 vrrp 100 ip 10.1.100.1
 vrrp 100 priority 120
 vrrp 100 track 11 decrement 11
 vrrp 100 track 12 decrement 11
interface Vlan2001
 vrrp 101 ip 10.1.101.1

! sw102
interface Vlan2000
 vrrp 100 ip 10.1.100.1
interface Vlan2001
 vrrp 101 ip 10.1.101.1
 vrrp 101 priority 120
 vrrp 101 track 11 decrement 11
 vrrp 101 track 12 decrement 11
```

一个目标不可达时，120−11＝109，仍高于对端的 100；两个目标均不可达时，120−22＝98，允许对端接管。跟踪只应用于各自首选的 VRRP 组。

**连续失败计数与 EEM 联动**

课程参考方案用 `delay down 10` 近似三次失败。它是时间去抖，不是失败次数计数器，还受 track 状态检测周期影响。最终配置改用 IOL 已实测支持的 IP SLA reaction 与 EEM，避免把时间延迟等同于题面的计数要求。

两台交换机均配置如下。SLA1 的连续三次 timeout 事件将 track11 置 Down，恢复事件将其置 Up；SLA2 对应 track12。VRRP 使用上面列出的 track11/12，原 track1/2 已删除。

```text
ip sla enable reaction-alerts
track 11 stub-object
 default-state up
track 12 stub-object
 default-state up
ip sla reaction-configuration 1 react timeout threshold-type consecutive 3 action-type trapOnly
ip sla reaction-configuration 2 react timeout threshold-type consecutive 3 action-type trapOnly

event manager applet M2_SLA1_COUNT3
 event ipsla operation-id 1 reaction-type timeout
 action 1.0 cli command "enable"
 action 2.0 cli command "configure terminal"
 action 3.0 cli command "track 11 stub-object"
 action 4.0 if $_ipsla_condition eq "Occurred"
 action 5.0 cli command "default-state down"
 action 6.0 else
 action 7.0 cli command "default-state up"
 action 8.0 end
 action 9.0 cli command "end"
 action 9.1 syslog msg "M2_SLA1 condition=$_ipsla_condition threshold=3"

event manager applet M2_SLA2_COUNT3
 event ipsla operation-id 2 reaction-type timeout
 action 1.0 cli command "enable"
 action 2.0 cli command "configure terminal"
 action 3.0 cli command "track 12 stub-object"
 action 4.0 if $_ipsla_condition eq "Occurred"
 action 5.0 cli command "default-state down"
 action 6.0 else
 action 7.0 cli command "default-state up"
 action 8.0 end
 action 9.0 cli command "end"
 action 9.1 syslog msg "M2_SLA2 condition=$_ipsla_condition threshold=3"
```

`ip sla enable reaction-alerts` 必须开启，否则本次实测即使 reaction 和 applet 均已配置，也没有产生 EEM 历史事件。这里没有配置外部 SNMP 接收者，trapOnly 用于 reaction 的事件动作，EEM 在设备内修改 stub 对象。

默认 Up 用于启动后的初始状态；若启动时目标不可达，需等待连续三次探测使状态降为 Down。正常运行时发生 Occurred/Cleared 后，状态由 EEM 维护。没有通过 reload 验证启动边界，不将其计为已验收项。

本镜像虽接受 `action track set` 语法，但实测发生事件后 stub 状态仍为 Up，不能使用该动作完成联动。最终 applet 通过本机 CLI 修改 `default-state`；这会改变运行配置，因此故障测试结束后先核对对象恢复为 Up，再执行保存。

三次探测判定和 VRRP 接管不是同一时刻：探测以 5 秒为周期，timeout 为 400 ms；三次失败触发状态降低后，仍有 VRRP 通告与对端接管处理时间。`threshold 400` 不是失败次数参数。

由 DC 的 sw211 为总部两个 VLAN 分配地址，配置中继和接入侧 DHCP Snooping。

客户端首次请求地址时通常尚无可用 IPv4 地址，请求通过所在 VLAN 广播。DHCP relay 在用户网关接收请求，将它转交给 DC 服务器；服务器按中继信息选择地址池，返回地址、掩码、网关等参数。


`ip helper-address` 位于用户侧三层入口；DHCP Snooping 位于接入交换机，区分可信上联与不可信终端口。Option82 是附加的中继信息，含有它的请求还依赖汇聚设备的信任设置。

| 对象 | 位置 | 本实验作用 |
| --- | --- | --- |
| 地址池及排除范围 | sw211 | 分配 `.101—.254`，保留 `.1—.100` |
| `default-router` | DHCP pool | 下发 VRRP VIP，终端使用虚拟网关 |
| `ip helper-address` | sw101/sw102 的用户 SVI | 将请求送到 `10.2.255.211` |
| Snooping trust | sw110 的 Po1/Po2 | 接受合法上游的服务器报文 |
| Snooping binding | sw110 | 对照终端 MAC、VLAN、入口和租约地址 |

helper 目标地址与客户端收到的 Server Identifier 可能不同，续租单播路径需要另外检查。

IPv6 终端通过 RA（路由器通告）获取前缀及默认路由器信息，SLAAC 使用前缀生成全局地址。默认网关通常指向路由器的 link-local 地址，与终端的全局地址用途不同。

<p><strong>课程原页</strong></p>

在总部四台三层设备间运行 IPv6 EIGRP，发布用户前缀和 Loopback。

IPv6 网关解决终端离开本 VLAN 的入口，EIGRP 再让总部路由器和汇聚交换机交换用户前缀与 Loopback 路由。命名进程为 `ccie`，IPv6 地址族使用 AS65001。

本节区分邻接接口与前缀发布接口：物理三层链路建立邻居；用户 SVI 和 Loopback 保持 passive，仅发布已有前缀。`af-interface default shutdown` 默认停用地址族接口，指定接口再显式启用，限制未来新增接口自动参与。

| 接口配置 | 效果 |
| --- | --- |
| `shutdown` | 停用该 EIGRP 地址族接口 |
| `no shutdown`＋`passive-interface` | 允许发布接口前缀，不建立邻居 |
| `no shutdown`＋`no passive-interface` | 启用接口并允许建立邻居 |

`show ipv6 eigrp neighbors` 核对邻接范围，`show ipv6 route eigrp` 核对 D 路由。邻居队列 Q 为 0 表示采样时没有待发送的可靠更新。



### 接口范围

使用命名进程 ccie、AS65001，不新增 IPv6 地址、不使用路由过滤。邻接仅允许在总部四台设备之间的物理三层链路建立，用户 SVI 发布前缀但不建立邻居。未来新增 IPv6 接口在明确允许前不能自动运行协议或发布前缀。

| 设备 | 允许建立邻接的接口 | 仅发布已有前缀的接口 |
| --- | --- | --- |
| r11 | e0/1（r12）、e0/2（sw102）、e0/3（sw101） | Loopback0：`2001:db8:1:255::11/128` |
| r12 | e0/1（r11）、e0/2（sw101）、e0/3（sw102） | Loopback0：`2001:db8:1:255::12/128` |
| sw101 | e0/0（r11）、e0/1（r12） | Vlan2000、Vlan2001 |
| sw102 | e0/0（r12）、e0/1（r11） | Vlan2000、Vlan2001 |

四台基线均未运行 IPv6 EIGRP。物理邻接使用已有 link-local 地址；r11 的运营商接口 e0/0 虽已有 IPv6，但不允许加入本次 EIGRP。

### EIGRP 配置

只配置 passive-interface default 会阻止邻接，但不能表达“新接口前缀也不自动发布”。本次使用 af-interface default shutdown，并保留默认 passive；指定物理链路显式 no shutdown、no passive-interface，允许发布的 Loopback/SVI 仅 no shutdown，保持 passive。

r11 的实际配置如下：

```text
configure terminal
router eigrp ccie
 address-family ipv6 unicast autonomous-system 65001
  af-interface default
   shutdown
   passive-interface
  exit-af-interface
  af-interface Ethernet0/1
   no shutdown
   no passive-interface
  exit-af-interface
  af-interface Ethernet0/2
   no shutdown
   no passive-interface
  exit-af-interface
  af-interface Ethernet0/3
   no shutdown
   no passive-interface
  exit-af-interface
  af-interface Loopback0
   no shutdown
  exit-af-interface
 exit-address-family
end
```

四台已按上表对应接口完成配置；r12 的接口配置结构与 r11 相同。sw101/sw102 在物理口 Ethernet0/0、Ethernet0/1 解除 shutdown 和 passive，Vlan2000/2001 仅解除 shutdown。未新增 IPv6 地址，未配置路由过滤。初始配置与接口输出见 M2-1.7 原始输出。

优化 DC 的 OSPF 前缀发布，保留服务及 DHCP 路径，并补齐分支路由。

DC 路由优化的目标是减少仅用于设备互联的传输前缀，同时保留服务及终端所需路径。OSPF prefix-suppression 抑制符合条件的接口前缀通告，接口例外使用 `ip ospf prefix-suppression disable` 保留。

被动接口与前缀抑制作用不同：passive 关闭邻接建立，接口前缀仍可发布；prefix-suppression 调整前缀通告范围。DHCP 的 Server Identifier 如果落在被抑制网段，客户端可能无法完成单播续租，即使服务器 Loopback 仍然可达。

本节保留该依赖冲突的失败、回退和恢复记录。分支 EIGRP 路由在 G4 补齐后再引入 OSPF，最终状态见文末依赖回补。



**节点与依赖**

sw212 使用 L2 20190423 镜像，已与 sw201/sw202/sw211 建立 FULL 邻接。按需启动已有 r21、r22、r23、r24，沿用 L3 15.7 镜像和课程配置，没有创建替代 vEdge。启动采样为 14 IOL、1 VPCS，EVE 内存使用率 24%、swap 0；该值是当时采样，不是所有节点的峰值资源。

题目包含真实 vEdge 的 Vlan3999 邻接、内部传输前缀优化，以及 r24 发布分支与隧道 Type-5 LSA。本节初始实施时尚无真实 Edge；后续 G5 已接入真实设备，但 Vlan3999 产品邻接仍无本项验收记录。

### DHCP 路径冲突与回退

M2 1.5 实测客户端的 DHCP Server Identifier 为 sw211 物理口 10.2.22.2，而 helper-address 指向 Loopback 10.2.255.211。两者不能混淆；仅保证 Loopback 可达不足以证明客户端单播续租路径可用。

```text
configure terminal
router ospf 1
 no prefix-suppression
end
write memory
```

此回退保留服务路径，未将“内部路由数量绝对最少”标为完成。后续需明确 DHCP Server Identifier 的稳定地址方案及课程配置上下文限制，再缩小保留范围；没有擅自添加静态路由绕过问题。`*-verification.txt` 保留失败证据，`*-dhcp-path-rollback.txt` 与 `*-restored.txt` 记录恢复。
