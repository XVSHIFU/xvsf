# 浏览器写作区

基于 Vditor 4.0.0，使用分类笔记本、多文档标签、本机草稿与 GitHub PR 管理博客文章。源码在本目录，生成资源与预览文件在被忽略的 `tmp/` 中。原型 `tmp/vditor-workbench` 作为迁移前副本保留，不再作为开发入口。

## 本地使用

在仓库根目录运行：

```powershell
npm ci
npm run workbench:dev
```

打开 <http://127.0.0.1:4319/>。继续使用相同浏览器、主机名和端口，即可保留原体验版草稿；IndexedDB 原有 `drafts` 表保留，升级时增加远端文章缓存。如果提示升级被阻止，关闭其他旧版体验窗口，再刷新。

本机输入自动保存，`Ctrl S` 也只保存本机。导出 Markdown、历史版本与本机回收站在“更多文章操作”中；导入、批量分类、草稿备份与恢复在侧栏“文章管理”中。备份恢复会创建新副本，不覆盖原文章。

## GitHub 文章同步

1. 创建 fine-grained personal access token，只选择 `XVSHIFU/xvsf` 仓库，授权 **Contents: Read and write** 和 **Pull requests: Read and write**。
2. 点击顶部“GitHub”，填入令牌，选择“连接并读取文章”。读取 `main` 中的文章，并显示本工作区已创建的待合并文章版本。本机未同步的修改保留。
3. 编辑后点击文章栏“同步”，核对文件路径与草稿/发布时间，再选择“保存到 GitHub”。新文章默认为草稿；发布文章需要填写摘要。
4. 工作区创建 `workbench/post-<文章标识>-<内容标识>` 分支及 PR。未合并前继续编辑同一篇文章，会更新同一 PR。
5. 点击成功通知里的“查看并合并”，或“更多文章操作 → 查看待合并 PR”。检查通过后在 GitHub 合并到 `main`，现有 Pages 工作流构建发布。

`main` 的现有规则要求 PR；工作区不会直接写入、强制推送或修改主分支保护。PR 不自动合并。草稿状态只影响博客展示；这个仓库公开，保存进去的 Markdown（包括草稿、PR 与分支）仍是公开内容。

令牌仅在当前页面内存中，刷新后需重新填写，不写入浏览器持久存储、备份或构建资源。“清除令牌”只清除当前页面凭据。图床使用独立配置 `XVSHIFU/Picture-bed` / `img` 分支，继续支持选择、粘贴、拖入图片。

## 访问与安全边界

`/xvsf/admin/` 是公开的静态编辑器，没有独立的管理员账号或服务端登录。其他人打开时只能看到编辑器与示例，并在自己的浏览器中新建草稿；发布资源不含你的令牌、文章缓存或本机草稿。公开仓库的文章和 PR 本来就能从 GitHub 读取，不视为私密内容。

每次上传或同步都由 GitHub API 校验令牌所属身份、目标仓库权限和分支规则。没有有效令牌，或访客自己的令牌无权写入你的仓库，就不能通过此入口改变你的文章、上传到你的图床。GitHub 网页中的登录状态不会自动授予本页面权限；请求使用显式 Bearer 令牌、`credentials: omit`，拒绝重定向，令牌仅发给 `https://api.github.com`。

浏览器端已启用以下保护：

- Vditor/YAML 的脚本随锁定版本依赖一起构建，不从第三方 CDN 加载脚本。页面 CSP 只允许本站脚本，禁止内联脚本、事件处理代码、`eval`、表单提交、对象嵌入与外部框架；网络接口仅允许本站及 GitHub API。为显示文章插图，图片仍允许 HTTPS 来源。
- 编辑器开启 Markdown HTML 清理；Pages 预览放在禁止脚本、没有同源权限的 iframe 中。本地 Hugo 预览使用独立 loopback 端口、Origin 和随机令牌校验；本地服务不会进入线上构建。
- 本机草稿保存在当前浏览器 IndexedDB 中，凭据不写入 IndexedDB、localStorage、sessionStorage 或备份。刷新页面后需要重新输入凭据；退出共享电脑前应导出所需草稿并清理站点数据。
- 同步仅创建或更新文章分支及 PR，不自动合并；写入时核对 Git blob SHA，避免覆盖另一台设备的更新。

这些保护有明确边界：细粒度令牌的 Contents 写权限覆盖所选仓库，并非只授权 `content/posts/`。路径检查与“不自动合并”是本应用的行为，不能约束拿到令牌后直接调用 API 的人；当前主分支要求 PR，但未要求另一个账号审批。令牌泄露后须立即在 GitHub 撤销；建议分别给文章与图床设置短期有效的最小权限令牌（例如 30–90 天），并给 GitHub 账号开启双重验证。双重验证不对每次令牌调用再次弹出验证。

本站其他同源页面、浏览器扩展和脚本依赖仍属于信任范围；仅存内存并不能防止已经在页面中执行的恶意脚本使用凭据。不要把未经审查的脚本加入博客。若需要“未经登录连编辑器都不能打开”，需要部署在可校验身份的服务或网关后，并确保源站无法绕过；前端密码框、隐藏 URL 和 `noindex` 都不是访问控制。当前个人账号的公开 GitHub Pages 没有路径级的管理员登录。

严格 CSP 下需要 `eval` 的特殊图表渲染器可能无法预览；普通 Markdown、代码高亮和 KaTeX 使用本地资源。不要为启用特殊渲染器放开 `unsafe-eval`。

## 版本与失败处理

- 写入前核对文章的 Git blob SHA，提交时携带期望 SHA。另一个设备或窗口更新后，不自动覆盖远端。
- 冲突对话框展示本机与 GitHub 版本。“保留副本并读取远端”先持久保存本机副本，再更新原文章；副本默认为草稿，可对照合并。远端已删除时，原记录保留在本机回收站。
- 断网、权限不足或 PR 创建失败时，草稿保留并提供错误说明。重试会核对已写入内容，避免重复内容提交；PR 创建失败后可以补齐权限再重试。
- 同步任务固定文章与内容版本。提交期间新增的文字保留为待同步修改，切换文章不会更换提交目标。
- 首次同步使用当前文件名；已有仓库文章保持原路径。远端重命名或删除请在 GitHub 操作，再重新读取；本机回收站不会删除仓库文件。
- 支持 `content/posts/` 下的独立 `.md` 文件，每篇不超过 2 MB。目录入口 `_index.md` / `index.md`、嵌套文章包和其他仓库路径不通过此入口写入。

## 预览与构建

本地“预览”运行已安装的 Hugo，在 `tmp/workbench-preview/` 中隔离构建，并从另一个 loopback 端口展示实际博客主题。文章不会因此提交。

GitHub Pages 版本提供隔离的 Markdown 预览，不调用 Node 接口，不执行 Hugo 短代码。实际主题和短代码效果通过本地 Hugo 预览查看。公开构建不会打包本机文章副本或草稿；连接 GitHub 后再读取文章。

```powershell
# 仅生成静态写作区
npm run workbench:build -- tmp/workbench-public
# 整站构建，包含 /admin/
npm run build:site -- --minify --panicOnWarning --cleanDestinationDir --destination .ci-site/xvsf
# 同步与构建边界测试，使用模拟 GitHub API
npm run workbench:test
```

`scripts/build-workbench.mjs` 只复制明确列出的浏览器文件、锁定版本的 Vditor/YAML 运行资源及许可证。Node 服务、测试、设计文档和临时文件不进入 Pages 产物。Vditor 为 MIT，YAML 为 ISC；依赖版本与完整性由根目录 `package-lock.json` 固定。

开发检查：同步模型测试覆盖新建/更新、PR 复用、合并后的继续编辑、并发冲突、丢失响应重试、权限错误、路径边界与公开产物。自动化浏览器验证使用隔离环境和模拟 API，另做真实 GitHub 只读验证；自动化测试不创建真实文章或 PR。2026-10-09 已由使用者在本地验证真实图床上传与文章同步，并创建测试文章 PR #45。

Windows 的 `core.autocrlf` 可能使原有 `frontmatter:check` 在工作副本上报告换行格式差异。已用 Git 中保存的文章原始字节复核；不要为通过该项检查批量重写正文。现有内容质量提示、PR 检查与部署结果仍由仓库工作流决定。
